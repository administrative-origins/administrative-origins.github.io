Task and inputs

Each agent acts as an expert human coder assigning the state of employment for 75 place strings. The instructions say accuracy matters more than speed and each row gets individual consideration.
It reads a per-batch dossier first. The dossier has each string, its n and years, and the context columns (appointed states, born states, departments, offices), treated as suggestive evidence only. It also has pre-pulled hits from the abbreviation key and the hand-entered tables.
It may grep the full dictionary text and the hand-entered CSVs itself.
It writes city_employed, state_employed_clean, confidence, notes for every row and runs a validator before finishing.

Decision rules

Format: Use full state names, “DC” for Washington, and the country name for foreign places. Canal Zone is “Panama”, and territories use their own names.
Blank when unsure: Leave the state blank if the person worked in multiple states, if the name is ambiguous and context doesn’t clearly resolve it, or if the string is generic or garbled.
Rivers and regions: Regions (Mississippi River, Atlantic coast) are blank. A river system or harbor entirely or nearly entirely in one state gets that state (Saginaw River → Michigan).
Fixed sites: Forts, navy yards, arsenals, lighthouses and ports get the state where they are physically located.
Ambiguous names: Names like Portland, Springfield and Charleston are filled only when one state clearly dominates in the context and other evidence agrees.
Vessels: Tenders, light vessels, snag boats, dredges, towboats and transports are blank unless the string itself names a single-state place. Appointee majority alone isn’t enough. This rule was added after batch 017.
Confidence: Every row is high, medium or low. Medium and low filled rows must carry “REVIEW” in the notes.

Evidence tags

Every note must start with [DICT], [WEB] or [NOHIT], followed by a short reason.
[NOHIT] is forbidden for truncated abbreviations (Ft, Cmp, Fld, Tndr, Stmr and similar). Those need a real dictionary decode or a web search.
The validator checks row count, order, confidence values, tags and REVIEW flags.
Agents must use WebSearch for places they can’t place confidently, and are told how to load it.

Where this is falling short

Early versions: The agents ran against earlier versions of the instructions. Batches 001–008 and some later ones were launched before the abbreviation rule and the vessels policy existed, so they filled many vessels from appointee majority. I plan to re-check those in a final pass.
Web search: Several agents (013, 015, 019 and others) used web search lightly or not at all, even when they flagged places that needed it. The validator can’t enforce that.
Dictionary: Many [DICT] tags rest on generic hits like “Ft = Fort” rather than the specific place, because the key’s two-column OCR is messy.
Review: A final audit will re-verify the abbreviated-name rows and the vessel fills before anything goes into your crosswalk.
